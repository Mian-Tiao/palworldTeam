# 需求規格書:幻獸帕魯隊伍與打工最佳化系統

> 建立日期:2026-07-16
> 狀態:草稿(Draft)

## 1. 專案概述

一個給幻獸帕魯(Palworld)玩家使用的網頁輔助工具。玩家從自己喜歡的帕魯出發,系統依屬性克制、種族值、主動技能與夥伴技能,篩選出對指定頭目或屬性組合傷害最大的隊伍;第二階段再加入基地最佳打工配置功能。供開發者本人與朋友使用,部署於網路上,玩遊戲時開在旁邊即查即用。

## 2. 問題陳述與目標

**問題**:幻獸帕魯有 200 多隻帕魯,屬性克制、技能與夥伴技能組合繁多。玩家想用自己喜歡的帕魯,但不知道怎麼搭配才能對特定頭目打出最大傷害;基地打工安排也只能靠感覺,效率不明。

**目標**:

- 讓玩家輸入喜歡的帕魯與目標敵人後,快速得到傷害最大的隊伍建議,且計算過程透明可驗證
- 第二階段:依基地工作需求推薦最佳打工配置
- 遊戲改版時,透過半自動工具即可更新資料,不需持續爬蟲

## 3. 目標使用者

- **主要使用者**:開發者本人與一起玩幻獸帕魯的朋友(少數人,無需會員系統)
- **使用情境**:玩遊戲時在電腦瀏覽器開啟本工具,查詢隊伍搭配建議;打完頭目前先查一下該帶誰
- **痛點**:攻略網站只有單隻帕魯的數值,沒有「從我喜歡的帕魯出發算出最佳隊伍」的工具;自己排列組合太花時間

## 4. 功能需求

| 編號 | 需求描述 | 優先級 |
|------|----------|--------|
| FR-1 | 帕魯資料庫:收錄全帕魯的屬性、種族值、主動技能(威力/屬性/冷卻)、夥伴技能、工作適性 | 高 |
| FR-2 | 帕魯選擇:使用者可搜尋並選擇自己喜歡的帕魯,作為隊伍的**固定成員**(以其為中心量身配隊) | 高 |
| FR-3 | 目標敵人設定(可選):可從頭目清單選擇具體目標,或指定敵方屬性組合;未指定時以通用傷害計算 | 中 |
| FR-4 | 隊伍推薦:以選定的喜愛帕魯為固定成員,系統補齊其餘隊員,計算出整體傷害最大的隊伍組合,依傷害排序呈現 | 高 |
| FR-5 | 計算透明化:每個推薦結果須顯示傷害拆解(屬性克制倍率、種族值、技能傷害、夥伴技能加成) | 高 |
| FR-6 | 半自動資料更新:提供匯入工具/腳本,遊戲改版時執行一次即可更新帕魯資料 | 中 |
| FR-7 | (第二階段)最佳打工配置:輸入基地工作需求,推薦帕魯的打工分配 | 低 |

### 傷害計算範圍(FR-4、FR-5)

- **納入計算**:屬性克制倍率、攻擊種族值、主動技能(威力/屬性/冷卻)、夥伴技能加成
- **夥伴技能的納入範圍**:僅計算「編入隊伍即生效的加成型」夥伴技能(如提升攻擊力、強化特定屬性傷害);騎乘、搭乘射擊等需操作觸發的類型暫不納入
- **等級**:由使用者選擇計算等級(全隊套用同一等級,預設值見 Q-4b),依等級成長公式換算能力值
- **不納入計算**:被動技能詞條(隨機性高)、濃縮與魂強化等個體培養差異,使用者不需逐隻輸入培養狀況

## 5. 範圍外(Out of Scope)

- 配種計算機
- 被動詞條與個體培養程度的輸入與計算
- 會員系統、登入功能
- 手機版面優化(以電腦瀏覽器為主)
- 從社群網站自動定期爬取資料(採半自動手動觸發更新)

## 6. 成功標準與驗收條件

1. **計算透明可驗證**:任一推薦隊伍都能展開查看傷害計算過程(克制倍率、技能傷害拆解、夥伴技能加成),使用者可自行核對數字來源
2. **操作快速簡單**:從選帕魯到看到推薦隊伍,操作流程不需說明書即可完成;送出後數秒內顯示結果
3. 朋友可透過網址直接使用,無需安裝或註冊

## 7. 限制與假設

**限制**:

- 技術棧為專案既定:後端 FastAPI、前端 React、本地開發 SQLite、正式部署 Render.com + Render PostgreSQL
- 介面使用繁體中文,帕魯與技能名稱以中文顯示
- 以電腦瀏覽器為主要使用環境
- 資料更新採半自動:改版時執行匯入腳本更新,不建置自動同步

**假設**(訪談中未逐項確認,標示為假設):

- 隊伍人數上限依遊戲設定為 5 隻(見 Q-1)
- 帕魯基礎資料可自社群資料庫(如 Paldb.cc、GitHub 社群資料集)取得(見 Q-3)

**已確認的決策**(2026-07-16 訪談後補充確認):

- 產品核心流程為「以喜愛帕魯為中心量身配隊」:喜愛帕魯是隊伍固定成員,系統補齊其餘隊員;目標敵人為可選條件
- 傷害計算等級由使用者選擇,全隊套用同一等級
- 夥伴技能僅計算編隊即生效的加成型,騎乘類暫不納入

## 8. 開放問題

| 編號 | 事項 | 說明 |
|------|------|------|
| Q-1 | 隊伍人數上限 | 假設為遊戲預設的 5 隻,需確認是否要支援其他隊伍規模 |
| Q-2 | 頭目清單初版收錄範圍 | 已確認頭目為可選條件、非核心流程;初版頭目清單建議先收錄塔主,是否擴充至野外傳說頭目待確認 |
| Q-3 | 資料來源選定 | 具體採用哪個社群資料源(Paldb.cc / GitHub 資料集),需確認資料完整度、格式與使用條款 |
| Q-4b | 等級選擇的預設值與範圍 | 已確認等級由使用者選擇;等級選單的預設值(建議 Lv50)與可選範圍(1~最高等級)待確認 |
| Q-6 | 傷害公式細節 | 遊戲實際傷害公式(含防禦計算方式、等級成長公式)需以社群考據資料為準,採用哪一版公式待確認 |
| Q-7 | 打工配置需求細節 | 第二階段功能尚未深入訪談,開發前需補充訪談(輸入格式、基地數量、是否考慮帕魯數量限制) |

> 已結案:Q-4(原「統一計算基準」,改為使用者選擇等級)、Q-5(夥伴技能僅計算編隊即生效的加成型,騎乘類暫不納入)——見「限制與假設」的已確認決策。
